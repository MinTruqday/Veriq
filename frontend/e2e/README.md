# Kiểm chứng E2E giao diện

Playwright ghi báo cáo JSON theo từng lượt chạy trong thư mục tạm của hệ điều hành theo mặc định (`veriq-e2e/<thời điểm>-<pid>/results.json`). Ảnh, video hoặc trace được lưu cạnh báo cáo trong `artifacts/`; trace chỉ được giữ khi test thất bại. Có thể đặt `E2E_REPORT_DIR` để chọn thư mục báo cáo khác. Các bài UI giả lập API dùng `E2E_FRONTEND_API_URL`, rồi `NEXT_PUBLIC_API_URL`, làm đích chặn request để không phụ thuộc cứng vào cổng mặc định.

Các test UI dùng phản hồi giả chỉ chứng minh hành vi giao diện với hợp đồng đã mô phỏng; chúng không chứng minh API hoặc phân quyền backend hoạt động thật.

`role-responsive-live-readonly.spec.js` là bộ smoke chỉ đọc qua giao diện và API thật. Chỉ bật bằng `E2E_LIVE_READONLY=true`; cần đặt `E2E_BASE_URL`, `E2E_API_URL`, `E2E_LIVE_PROJECT_ID`, cùng token riêng `E2E_ROLE_BA_TOKEN`, `E2E_ROLE_QA_TOKEN`, `E2E_ROLE_TESTER_TOKEN`, `E2E_ROLE_DEVELOPER_TOKEN`, `E2E_ROLE_VIEWER_TOKEN` và `E2E_ROLE_ADMIN_TOKEN` cho các vai trò muốn kiểm tra. Ứng dụng và API bắt buộc chạy trên loopback. Với thành viên dự án, tập route được lấy trực tiếp từ capability metadata của navigation đang dùng trong ứng dụng, gồm mọi route workspace đã đăng ký, route nhóm Lập kế hoạch, các mục con Ca kiểm thử, tìm kiếm tri thức và URL cũ có chuyển hướng; Sprint chỉ được đưa vào khi dự án thực là Scrum. Mỗi route được phép/chặn được tính từ chính `permission`, `permissions` và `anyPermission` của metadata đối chiếu với `current_permissions` API, không gán quyền giả theo tên role. Bộ này xác nhận session/role thực, quyền truy cập các route đã đăng ký, điều hướng mobile, lỗi runtime trình duyệt và tràn ngang tại 1920, 1440, 1280, 768 và 390 px. Nó không tạo/sửa/xóa dữ liệu; nếu bất kỳ request ghi nào phát sinh thì lượt chạy bị đánh dấu thất bại. Báo cáo kèm metadata năng lực và kết quả từng route, phép đo độ rộng trang và ảnh desktop/mobile. Các route chi tiết cần ID thật (ví dụ Requirement/Test Case cụ thể) và mọi thao tác CRUD không nằm trong route-base smoke này; chúng cần fixture disposable/runtime phù hợp riêng.

Test so sánh ca kiểm thử với API thật có ghi dữ liệu: lưu bản ghép và tạo xung đột revision. Nó chỉ được chạy khi đồng thời xác nhận `E2E_DISPOSABLE_DATABASE=true`, `LIVE_COMPARE_DISPOSABLE_FIXTURE=true`, ứng dụng và cả hai địa chỉ API đều là loopback, có token QA hợp lệ, và project ID cùng hai cặp draft/Test Case key đều chứa cùng `LIVE_COMPARE_FIXTURE_NAMESPACE`. Đặt `E2E_FRONTEND_API_URL` hoặc `NEXT_PUBLIC_API_URL` làm địa chỉ API mà trình duyệt đang gọi; `LIVE_COMPARE_BACKEND_URL` là API Testing trực tiếp dùng để đọc/ghi ca so sánh. Trước khi ghi, test đọc lại project và từng draft để xác nhận chúng thuộc đúng namespace và đúng project. Hai case bắt buộc dùng hai draft khác nhau. Sau test phải hủy toàn bộ môi trường cơ sở dữ liệu dùng riêng cho lượt E2E.

API hiện có thể tạo project, draft và lưu trữ project, nhưng không có endpoint công khai để xóa project hay Test Case draft. Chức năng xóa draft hiện chỉ là thao tác nội bộ dùng cho rollback khi import. Vì vậy frontend không thể tự seed rồi teardown đáng tin cậy qua API; lưu trữ project không xóa dữ liệu. Không chạy live compare trên môi trường chứa dữ liệu người dùng. Muốn có vòng đời seed/cleanup tự động cần một môi trường DB dùng riêng và harness quản trị môi trường bên ngoài API nghiệp vụ; không thêm endpoint xóa chỉ dành cho test vào sản phẩm.

Bộ smoke chỉ đọc bổ sung kiểm tra toàn bộ route workspace cơ sở đã đăng ký theo quyền thật và năm viewport, cùng menu điều hướng mobile/khôi phục focus bằng Escape. Nó chưa thay thế ma trận toàn frontend FE-14: chưa bao phủ mọi route chi tiết cần ID dữ liệu, mọi thao tác CRUD, bàn phím/chạm trên từng widget, các luồng API allow/deny cho mọi endpoint, hay vòng đời seed/cleanup. Báo cáo JSON và trace là bằng chứng chẩn đoán cho các test đã chạy, không tự chứng minh các phần chưa chạy.
